# 黑白网格编码系统

## 📋 概述

黑白网格编码系统是 DataToText 插件的核心功能，用于替代 DataToColor 的 RGB 颜色编码方案。通过使用二值（黑白）编码，完全消除了不同屏幕 gamma 设置导致的颜色失真问题。

## 🎯 设计目标

1. **消除颜色敏感性**: RGB 颜色编码对 gamma、亮度、对比度非常敏感
2. **提高鲁棒性**: 二值编码只需区分黑白两种状态，容错率高
3. **保持数据容量**: 65×65 网格可容纳 108 个 DataToColor 字段（每字段 24 位）
4. **内置纠错**: 15% XOR 奇偶校验，可恢复部分损坏数据
5. **自动定位**: 四个角的 3×3 定位标记，支持自动旋转和倾斜校正

## 📊 技术规格

### 网格尺寸
- **逻辑网格**: 65×65 单元（4225 个单元）
- **显示尺寸**: 195×195 像素（每单元 3×3 像素）
- **显示区域**: 200×200 像素（包含边距）

### 数据格式
```
┌─────────────────────────────────────┐
│ 元数据 (32 bits)                     │
│ - 版本号 (8 bits)                    │
│ - 字段数量 (8 bits)                  │
│ - 保留位 (16 bits)                   │
├─────────────────────────────────────┤
│ 数据区 (2592 bits)                   │
│ - 108 个字段 × 24 bits               │
├─────────────────────────────────────┤
│ CRC32 校验 (32 bits)                 │
│ - IEEE 802.3 标准                    │
├─────────────────────────────────────┤
│ 纠错码 (~400 bits)                   │
│ - XOR 奇偶校验 (15%)                 │
└─────────────────────────────────────┘
总计: ~3056 bits
```

### 定位标记
```
四个角落的 3×3 图案:
█ █ █
█ ░ █  (中心白色，周围黑色)
█ █ █

用途:
- 检测网格边界
- 自动校正旋转和倾斜
- 验证网格完整性
```

## 🛠️ 实现文件

### Lua 端（插件）
1. **GridEncoder.lua** - 网格编码器模块
   - `PackFieldsToBits()` - 将字段打包为位流
   - `AddErrorCorrection()` - 添加纠错码
   - `CreateEmptyGrid()` - 创建空网格
   - `AddAlignmentMarkers()` - 添加定位标记
   - `FillDataToGrid()` - 填充数据到网格
   - `EncodeToGrid()` - 主编码函数

2. **DataToText.lua** - 主逻辑（集成）
   - `CollectAllFieldData()` - 收集 108 个字段数据
   - `InitializeGrid()` - 初始化 4225 个像素帧
   - `RenderGrid()` - 渲染黑白网格
   - `UpdateDisplay()` - 实时更新显示

3. **DataToText.xml** - 界面布局
   - `DataToText_GridFrame` - 网格显示区域（200×200 像素）
   - `DataToText_DataEditBox` - 文本显示区域（右侧）

### Node.js 验证程序
1. **grid_encoding_test.js** - 基础容量测试
2. **grid_capacity_test.js** - 详细容量分析

## 📖 使用方法

### 游戏内命令
```
/dtt              - 打开/关闭显示窗口
/dtt grid         - 测试网格编码器
/dtt test         - 运行所有单元测试
```

### 数据收集流程
```
游戏数据 → CollectAllFieldData()
         → 108个字段数组[0..107]
         → GridEncoder:EncodeToGrid()
         → 65×65黑白网格
         → RenderGrid()
         → 屏幕显示
```

### 解码流程（C# 端）
```
屏幕截图 → 定位标记检测
         → 网格区域提取
         → 二值化（黑白）
         → 位流提取
         → CRC32 验证
         → 纠错码校正
         → 108个字段解析
         → 游戏数据输出
```

## 🔍 字段映射

完整的 108 个字段定义见 `DATATOCOLOR_FIELDS.md`，主要类别：

- **基础信息 (0-9)**: 位置、朝向、地图、等级、尸体位置、布尔标志
- **玩家属性 (10-15)**: HP、法力、能量
- **目标信息 (16-19, 43, 56-59)**: 名称、HP、等级、GUID、施法
- **背包系统 (20-24, 44-45)**: 物品、装备、金钱
- **动作条 (25-37)**: 按钮状态、可用性、冷却
- **宠物信息 (38-39, 68-69)**: HP、GUID、目标
- **Buff/Debuff (41-42, 55, 79-84, 91-93, 104-105)**: 玩家/目标/焦点的增益和减益
- **战斗数据 (60-67, 70-76, 94-95)**: 施法、伤害、冷却、GCD
- **其他 (73, 97-103, 106-107)**: 对话、拾取、时间戳、元数据

## ⚙️ 配置参数

### GridEncoder.lua 常量
```lua
GRID_SIZE = 65              -- 网格尺寸
BITS_PER_FIELD = 24         -- 每个字段位数
TOTAL_FIELDS = 108          -- 总字段数
ERROR_CORRECTION = 0.15     -- 纠错率 (15%)
CORNER_MARKER_SIZE = 3      -- 角标记尺寸 (3×3)
```

### DataToText.lua 配置
```lua
UPDATE_INTERVAL = 0.1       -- 更新间隔 (0.1秒 = 10 FPS)
pixelSize = 3               -- 每单元像素数 (3×3)
```

## 📈 性能优化

### 已优化
- 像素帧创建只在初始化时执行一次
- 网格渲染只更新变化的像素
- 位运算使用 LuaJIT 的 bit 库（高效）

### 待优化
- 考虑降低更新频率（0.1s → 0.2s）
- 只在数据变化时重新编码
- 使用缓存避免重复计算 CRC32
